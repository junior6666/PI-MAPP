# 💻 系统资源管理器 - 使用教程

## 📋 功能简介

这是一款伪装成"系统资源管理器"的AI面试辅助工具，支持快捷键截图、OCR识别、LLM智能分析，并可通过手机实时接收分析结果。

---

## ⌨️ 快捷键说明

### 🚀 工作流快捷键

#### 快速分析模式（Alt + Z）
**适用场景**：快速查看屏幕上的面试题目并获取答案（约30秒，准确率高）

**工作流程**：
```
按下 Alt+Z → 全屏截图 → Kimi AI分析 → 结果推送到手机
```

**特点**：
- ⚡ 跳过OCR，直接调用视觉大模型（Kimi）
- 🎯 适合有明确题目的场景
- 📸 自动截取整个屏幕

---

#### OCR分析模式（Alt + X）
**适用场景**：需要精确识别文字后再分析（约20秒，速度较快）

**工作流程**：
```
按下 Alt+X → 截图保存 → OCR文字识别 → LLM分析 → 结果推送到手机
```

**特点**：
- 🔍 先OCR提取文字，再调用文本大模型
- 📝 可查看中间识别结果
- ⚙️ 可配置提示词和模型参数

---

### 🔄 模型切换快捷键

#### OCR模型切换（Alt + 1）
在 DeepSeek-OCR 和 EasyOCR 之间切换：
- **DeepSeek-OCR**：云端API，识别准确率高，依赖网络
- **EasyOCR**：本地模型，离线可用，速度稳定

**使用方法**：
```
按下 Alt+1 → 切换模型 → 下次截图使用新模型
```

**状态提示**：
- 终端显示：`🔄 OCR 模型已切换: XXX → YYY`
- 状态栏显示：`OCR 模型已切换为: YYY`
- 手机端推送：`[STATUS:OCR模型切换为YYY]`

---

#### Kimi主模型切换（Alt + 2）
在 Kimi-K2.5 和 QwenA3B 之间双向切换：
- **Kimi-K2.5**：Moonshot API，默认主模型
- **QwenA3B**：Qwen3-Omni-30B，SiliconFlow平台

**使用方法**：
```
按下 Alt+2 → 切换模型 → 下次快速分析使用新模型
```

---

#### 后备模型快速设置（Alt + 3 ~ Alt + 7）
直接将指定模型设置为主模型，灵活应对不同场景：

| 快捷键 | 模型名称 | 特点 | 适用场景 |
|--------|----------|------|----------|
| **Alt+3** | Qwen-VL-8B | 轻量级，速度快 ⚡ | 日常练习，快速响应 |
| **Alt+4** | Qwen-VL-32B | 中等规模，平衡 🎯 | 一般面试，性价比 |
| **Alt+5** | Qwen-VL-235B | 大规模，高精度 🧠 | 重要面试，复杂题目 |
| **Alt+6** | GLM-4.5V | 智谱GLM系列 🔮 | 备选方案，多样化 |
| **Alt+7** | Kimi-K2.5(SF) | SiliconFlow平台 🌟 | Kimi备用通道 |

**使用方法**：
```
按下 Alt+3~7 → 立即生效 → 下次快速分析使用新模型
```

**示例**：
```bash
# 切换到大规模高精度模型
按下 Alt+5
终端输出: 🔄 Kimi 主模型已设置为: Qwen3-VL-235B-A22B-Instruct
状态栏: Kimi 主模型已设置为: Qwen3-VL-235B-A22B-Instruct

# 执行快速分析
按下 Alt+Z
🤖 Qwen3-VL-235B-A22B-Instruct 请求中...
✅ Qwen3-VL-235B-A22B-Instruct 完成 (12.34s)
```

**技术说明**：
- 所有后备模型均使用 SiliconFlow API
- 切换时自动重置失败计数和成功计数
- 不影响自动降级策略（连续失败2次仍会切换）
- 程序重启后恢复默认主模型（Kimi-K2.5）

## ⚠️ 注意事项

### 1. 快捷键冲突
- 确保 `Alt+Z` 和 `Alt+X` 未被其他程序占用
- 如快捷键无效，可在"截图设置"中修改热键组合

### 2. 网络要求
- PC端和手机需在**同一局域网**内
- 防火墙需允许端口 `8765` 通行
- 如连接失败，检查手机配置中的IP地址

### 3. AI模型调用
- **主模型**：Kimi-K2.5（Moonshot API）
- **备用模型**：6个备选模型自动降级
  - Qwen3-Omni-30B
  - Qwen3-VL-8B/32B/235B
  - GLM-4.5V
  - Kimi-K2.5 (SiliconFlow)
- 主模型连续失败2次后自动切换备选模型

### 4. 耗时计算
- 总耗时从**快捷键按下时刻**开始计算
- 快速模式通常更快（跳过OCR）
- 网络延迟会影响实际体验

### 5. 隐私安全
- 截图会保存到 `./screenshots/` 目录
- API Key 已加密存储
- 建议定期清理截图文件

### 6. 系统托盘
- 最小化窗口后自动隐藏到托盘
- 双击托盘图标恢复窗口
- 右键托盘菜单可退出程序

### 7. 开机自启与守护（推荐）

#### 方案一：Windows 系统服务（⭐ 强烈推荐）
**位置**：帮助标签页 → ⚙️ 设置 → Windows 系统服务

**优势**：
- ✅ 无需外部脚本，直接嵌入系统
- ✅ 系统级保护，崩溃自动重启
- ✅ 登录时自动启动，真正7×24小时运行
- ✅ 以系统账户运行，更稳定可靠

**使用方法**：
1. 打开「帮助」标签页
2. 切换到「⚙️ 设置」子标签
3. 点击「📥 安装服务」按钮
4. 确认后即可实现自动启动和守护

**管理功能**：
- 📥 安装服务：注册为Windows计划任务
- 🗑️ 卸载服务：移除自动启动配置
- 🔄 刷新状态：查看当前运行状态

- 适合开发环境测试使用

## 🐛 常见问题

### Q: 快捷键无反应？
A: 
1. 检查是否有其他程序占用了快捷键
2. 尝试关闭输入法或使用英文输入法
3. 在"截图设置"中修改热键组合
4. 重启程序重新注册热键

### Q: 手机无法连接？
A: 
1. 确认PC端WebSocket服务已启动（状态栏显示"已连接"）
2. 检查IP地址是否正确（手机配置中可查看）
3. 关闭防火墙或添加端口例外
4. 确保手机和PC在同一WiFi网络下

### Q: 分析结果不准确？
A: 
1. 确保截图中题目清晰可见
2. 调整提示词模板（在主页标签页编辑）
3. 尝试切换不同模型（Alt+3~7）
4. 重要面试建议使用大规模模型（Alt+5）

### Q: 如何选择合适的模型？
A: 
- **日常练习**：Alt+3 (Qwen-VL-8B)，速度快
- **一般面试**：Alt+4 (Qwen-VL-32B)，平衡性好
- **重要面试**：Alt+5 (Qwen-VL-235B)，准确率高
- **网络不佳**：Alt+1 切换到 EasyOCR，Alt+6 使用 GLM
- **追求速度**：Alt+2 切换到 Kimi-K2.5

### Q: OCR识别失败怎么办？
A: 
1. 按 Alt+1 切换到 EasyOCR 本地模型
2. 检查网络连接（DeepSeek-OCR需要联网）
3. 确保截图清晰，文字可读
4. 系统会自动降级，连续失败2次后自动切换

### Q: 窗口黑色边框？
A: 已修复。如仍有问题，尝试调整窗口大小或重启程序。

### Q: 程序占用内存过高？
A: 
1. OCR引擎采用单例模式，首次加载后会常驻内存
2. 长时间运行建议定期重启程序
3. 退出程序时会正确清理所有资源
4. 任务中断时会立即释放大对象

### Q: 如何查看当前使用的模型？
A: 
1. 终端会显示每次调用的模型名称
2. 状态栏会显示最近的操作
3. 手机端会收到模型切换通知
4. 分析结果开头会标注使用的模型
